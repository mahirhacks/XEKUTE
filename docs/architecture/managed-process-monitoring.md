# Managed Process Monitoring

LLM-controlled lifecycle monitoring for long-running typed operations. Replaces the single process-kill timeout with a checkpoint-driven lifecycle so the model can follow, continue, or stop a managed process across agent turns without bypassing host-enforced security.

## Scope for this release

- `run_test_case` gains a managed lifecycle (`start` / `continue` / `stop` / `status`).
- `exec_command` is **unchanged** and exposes no continuation actions; managed behavior is gated off for this release.

## Identifier model

| Identifier | Role | Generated by |
| ---------- | ---- | ------------ |
| `operation_id` | Individual public tool-call invocation | Host/router, per call — never accepted from model input |
| `audit_id` | Audit trail for the operation | Host |
| `managed_operation_id` | Stable identity of the managed process for its whole lifetime | Host, at `start` |
| `checkpoint_id` | Single-use continuation token, minted at each checkpoint | Host |

The model supplies `managed_operation_id` and `checkpoint_id` on `continue`/`stop`, but not `operation_id`.

## Lifecycle

```
start ──► running ──► awaiting_decision ──► (model continues) running ──► ...
            │              │
            │              └─ host decision timer ─► terminate (MISSING_CONTINUATION_DECISION)
            │
            ├─ natural exit ──► terminal (success/failed)
            └─ hard deadline / destroy ──► terminate
```

The router marks the operation `checkpointed` (non-terminal) when a managed port returns a `continuation_required: true` checkpoint, persisting it so it survives the turn.

## Termination layers

- `stopFromModel` — model-issued `control: stop`. Validates and atomically consumes the checkpoint token, then terminates.
- `terminateFromHost` — host-forced, no checkpoint token required. Used for hard deadline, scope expiry, shutdown, cancellation, decision timeout, and continuation-budget exhaustion. Both converge on a single `finalize-once` guard for atomic, idempotent finalization.

## Deadlines and budgets

- `hard_deadline_at = min(policy maximum deadline, scope-decision expiry)`. Shutdown and cancellation are **excluded** from the initial calculation; they are independent asynchronous host events.
- `continuationDecisionTimeoutMs` — host-only stop when the model provides no `continue`/`stop` in time.
- `maxManagedContinuationTurns` / `maxManagedContinuationTokens` — host policy bounds on the checkpoint loop; exceeding either yields `MANAGED_CONTINUATION_BUDGET_EXCEEDED`.

## Output handling

- Byte-based bounds: `max_line_bytes`, `max_tail_bytes`, `ring_buffer_max_bytes`, `artifact_max_bytes`.
- The ring buffer stores already-redacted text. Oversized lines are truncated with `[TRUNCATED_LINE]`.
- Segmented artifacts persisted as bounded redacted chunks with `segment_count` and `truncation_reason`.
- `lines_available` = retained redacted lines currently in the ring buffer; `lines_returned = min(requested, available)`.

## Descriptor vs. runtime

- `ManagedProcessDescriptor` — persisted. Contains absolute deadlines, checkpoint sequence, continuation counters, evidence refs, cleanup state, and owner bindings.
- `ManagedProcessRuntime` — memory only. Contains the live child handle, streams, timers, and finalization lock.

## Restart semantics

Managed processes survive agent turns and context churn. Graceful application shutdown terminates managed processes. After an **unexpected restart**, PID reconnection is unsafe, so a managed operation with no live runtime is reported `PROCESS_NON_RECOVERABLE` unless a verified external process broker owns it (out of scope for this release).

## Result codes

`CONTINUATION_REQUIRED`, `MISSING_CONTINUATION_DECISION`, `OPERATION_RESUME_DUPLICATE`, `PROCESS_STOPPED`, `PROCESS_NON_RECOVERABLE`, `MANAGED_CONTINUATION_BUDGET_EXCEEDED`, `OPERATION_NOT_FOUND`, `CONTROL_INVALID`, `OPERATION_ALREADY_TERMINAL`.
