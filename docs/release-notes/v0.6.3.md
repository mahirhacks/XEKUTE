# XEKUTE 0.6.3

This release lets the agent sign in with the project's test accounts without
ever seeing their passwords or cookies. It also fixes three interface bugs and
splits the renderer into feature modules.

## Test accounts for the agent

- The agent can now use the Authentication Accounts saved in Settings >
  Project > Engagement. Its project context lists each account's label, role,
  username and variables: `{{account.<id>.username}}`, `{{account.<id>.password}}`
  and `{{account.<id>.cookie}}`.
- A variable works in any tool's input: browser fields, request headers and
  bodies, and terminal commands. XEKUTE substitutes the stored value only when
  the tool runs. Approvals, the audit log and the chat transcript keep the
  variable.
- Tool results come back with stored passwords and cookies masked as their
  variables, including URL-encoded, form-encoded and HTTP Basic forms, so a
  value that reappears later in terminal output, a file or a response header
  stays hidden.
- A variable for an unknown account or an unsaved field fails the tool call
  instead of sending the placeholder text.

## Interface fixes

- The embedded browser no longer goes blank when a menu or popover opens over
  it. A frozen snapshot of the page stays visible until the overlay closes.
- The section navigation in Settings > Project is now opaque, so scrolled
  content no longer shows through it.
- The question card icon stays at the top left on multi-line prompts.

## Internal

- The 22,500-line renderer composition root is now split into 66 feature
  modules under `src/ui/features` and `src/ui/core`, with shared renderer
  state in one `appState` object. Startup order and behavior are unchanged.
- Renderer tests load code by declaration name instead of text offsets, and
  the production gate checks every renderer module.
