# XEKUTE 0.6.5

This release improves agent planning, skill selection, interrupted-run recovery,
browser responsiveness, and startup reliability.

## Agents and context

- Each agent owns its checklist and loaded skills. The agent decides when to
  create a checklist; the decision model selects additional useful skills.
- Checklist updates enforce sequential work and prevent duplicate skill loads.
  Loaded skills appear in the chat activity feed.
- Resume an interrupted run with its checklist, or send a new prompt to start
  fresh. Steering messages and streamed thoughts retain their correct position.
- Improve context accounting, checkpoint recovery, encrypted session writes,
  and persistence during long runs.

## Browser and interface

- Bound browser actions and cleanup so a stalled page cannot hold an agent
  indefinitely. Preserve human ownership when control changes during an action.
- Apply wildcard scope consistently across browser, terminal, proxy, HTTP, and
  WebClone checks, while keeping exclusions and URL boundaries enforced.
- Scroll browser tabs horizontally and dismiss browser notices without closing
  the page.
- Load the editor, terminal, syntax highlighter, and diagrams when first needed.
- Keep diagram labels visible as SVG text without allowing embedded HTML.
- Fix startup visibility, native DevTools handling, and maximize/restore icons.
- Refresh checklist animation, Settings toggles, navigation placement, and panel
  visibility icons.

## Security and release checks

- Update DOMPurify, fast-uri, KaTeX, and Electron to address published advisories.
- Add adversarial hostname and rendered-markup regression coverage.
- Make production checks independent of ignored local scratch folders, pin
  production workflow actions, and stop packaging immediately on build failure.
- Audit build dependencies as well as runtime libraries. Separate installer
  building from release publishing and require release tags to come from main.

The Windows installer preserves existing application data and supports the
normal in-app update flow.
